## 借鉴来源（外部 H3 导演台工作流实测）
外部工作流画质好的主因不是二采/放大（它的 Refine/Upscale 节点是 **bypass**），而是：
1. **15 秒长段 + 多镜头提示词**，与 H3 的 22 帧段间连续匹配；
2. **纯 t2v（无参考图）**，避免 r2v 参考图带来的“透明假/假人感”；
3. **视频只编码一次**（VHS crf19），不走多次转码/硬字幕；
4. 采样档位与我们真实参数版几乎相同（8 步 / euler / cfg1 / 24fps）。

## 实验版做了什么
| 参数 | 稳定版（真实参数） | 实验版 |
|---|---|---|
| 任务类型 | r2v 参考主体生视频 | **t2v 文生视频** |
| 生成素材图 | 开（SDXL 素材+审核+LOCK） | **关**（省掉素材链，纯文生） |
| 每段时长 | 5.167s | **15s** |
| 段数 | 1 | **2** |
| 总时长 | ~5.2s | **~30s** |
| 分辨率 | 1344×768 | **1376×768** |
| 步数 | 8 | 8 |
| 转场 | AI自动 | **无** |
| 字幕 | 硬字幕 | **无** |
| Refine 二采 | 关 | 关（外部也未用；避免显存/稳定性风险） |
| 自动返工 | 开 | **关**（实验效率优先） |

## 测试方法
1. 重启 ComfyUI / 强刷页面（Ctrl+F5）；
2. 打开实验版工作流；
3. 粘贴一段 30 秒左右的剧本（或最多两段），运行；
4. 预期：2 段 15s、24fps、1376×768、无转场/无字幕、最终一次封装；
5. 记录：耗时、显存峰值、是否有 OOM/接缝/口型问题；与稳定版同提示词/同 seed 对比。

## 已知风险 / 判断标准
- 显存：1376×768 + 15s 长段比 1344×768 + 5s 更吃显存；OOM 会自动降级（关段间连续 + 每批1段），但画质/连续性会下降；
- 纯 t2v 不挂素材图，人物身份一致性依赖提示词与种子，弱于 r2v+LOCK 素材；
- 未开 Refine/放大（外部也没开），若需要更锐可后续做 A/B；
- scheduler 保守用 simple（外部 beta，列为 A/B 项，不直接上）；
- 关自动返工后，明显崩坏的段不会被自动重跑。
