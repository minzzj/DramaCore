## 一、C 部分：阶段化显存调度（用户核心新逻辑）

### 理论计算证明它不是优化项，而是必需品

新增 `scripts/theory_model.py`，每个数字来自**磁盘实测**：

| 件 | 体积 |
|---|---|
| 视频 UNET（ref2va int8 剪枝） | 19.53 GB |
| 文本编码器（qwen3vl-32b nvfp4） | 14.61 GB |
| 视频 / 音频 VAE | 4.85 / 0.56 GB |
| **一次性全加载** | **39.55 GB** |
| **阶段化峰值** | **24.94 GB** |

**在 5090 32 GB（预留 2 GB，可用 30 GB）上：**

```
一次性全加载 -> 超 9.55 GB  -> 必然 OOM
阶段化       -> 余 5.06 GB  -> 装得下
```

**结论：一次性全加载装不下，必须阶段化。** 这是量化证据，不是猜测。

### 效率量化（10 段）

| | 模型加载次数 | 时长 |
|---|---|---|
| 逐段交替 | 22 次 | 1590 s |
| 阶段化批量 | **5 次** | **825 s** |
| 节省 | 17 次（4.4x） | **765 s（48.1%）** |

### 实现与实测

`bettercomfyui/pipeline/phases.py` -> `VramPhaseScheduler`：

```
P0 提示词   DeepSeek API     （不占显存）
P1 素材     素材图模型        加载 → 批量生成全部 → 卸载
P2 视频     minimax_h3        加载 → 批量生成全部 → 卸载
P3 审核     审核模型          加载 → 统一审核 → 卸载
P4 重生成   minimax_h3        加载 → 只重生成不合格 → 卸载
P5 成片     ffmpeg           （不占显存）
```

**四条硬规则**：批量优先 / 切换必验（`/free` 后核对显存真降）/ 只驻留 1 个模型
（`vram_budget_gb` 门禁）/ 可断点续跑。

**真实 ComfyUI 实测 `/free`**：

```
显存快照: device=cpu total=15.747GB used=11.872GB
/free ok=True status=200
verified=True | 已核验：已用显存下降 0.101 GB
before.used=11.903 -> after.used=11.802
```

调度核心指标（假显存验证，不依赖 GPU）：`卸载次数=4，最大驻留=19.5GB = 单模型最大值`
-> 证明同一时刻只有一个模型驻留。

## 七、踩坑汇总（防止以后重犯）

1. **`default.yaml` 必须由 `dump_config(Config())` 生成**，手改必被测试抓到。
2. **两个工具口径必须一致**：棘轮脚本曾仍用"按文件名排除"（报 12），测试用"按路径"（报 9）。
3. **`SegmentOverrides` 没有 `effective()`**，真正合并方法是 `resolve(cfg)` 返回 `(生效值, 被覆盖字段)`。
   写错时异常被 `except` 吞掉，表现为"单段覆盖不生效"。
4. **风格不能重复注入**：桥接拼一次 + 导演台再拼一次，提示词里出现两遍「全片视觉风格」。
   风格是导演台职责。
5. **`/queue` 返回空 body**，不能 `json.load`；`JobRef` 需要 `(job_id, executor)` 两参数。
6. **`SegmentGenerator` 强制要求 R3 门禁依赖**（store 或 lock_resolver），测试需给假 resolver。
7. **`PreviewAny` 的 `source` 必须链到存在的输出索引** —— 桥接只有 3 个输出，
   链到索引 3 会静默不执行下游。
