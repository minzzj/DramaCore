跨段虚线：

**规则**：项目可打开/关闭/新建/删除；打开项目必须加载三件套（素材库、章节列表、生成进度）；新建项目创建空素材库。

### SG1 剧本拆解与提示词（dot L18–L51，边 L235–L274、L366）

主链：`A 剧本输入（可多章节）→ A1 程序读取当前项目素材库已有素材清单 → A1B 素材库是否为空？`
- `A1B --空--> A5 跳过注入直接进入模型选择`
- `A1B --非空--> A2 程序生成已有素材清单：类型+序号+名称+锁定状态 → A3 程序原样注入到系统提示词 → A4 明确指令：以下素材已存在，不要重复生成，只输出新素材 → A5`
- `A5 → B 用户选择提示词生成模型`
- `B --外部大模型--> B1 调用外部AI → B3 开发者可自配接口 → C`
- `B --本地模型--> B2 调用千问 → B4 本地推理 → B5 本地模型提示词适配：简化约束指令格式 → C`
- `C 读取系统提示词+已有素材清单+约束指令` → `C1 预置模板`、`C2 可替换变量`、`C3 输出语言`、`C4 输出格式JSON+分隔符`、`C5 分镜粒度`、`C6 风格标签库`（六者均 → `D`）
- `D AI理解与拆解剧本 → E AI仅输出新增素材提示词` → `E1 角色图提示词（仅新增）`、`E2 场景图提示词（仅新增）`、`E3 物品图提示词（仅新增）`、`E4 分镜图提示词（仅新增）`、`E5 最终视频提示词`
- `E1–E4 → E6 程序按名称确定性匹配：名称归一化`，三分支：`E7 已存在则丢弃不生成`、`E8 不存在则采纳送入生成`、`E9 疑似重复则标记待人工确认`
- `E5 --直接--> J_IN`（最终视频提示词绕开素材生成，直接进导演台）
- `Z --注入开关--> A3`、`Z --注入--> C`（全局配置注入）

**规则/硬约束**：
1. **确定性注入**：由程序读取素材库清单，生成"类型+序号+名称+锁定状态"清单并**原样**注入系统提示词，再附明确指令"已存在不要重复生成，只输出新素材"。禁止让 AI 自行判断素材是否存在（愿景 §八.1）。
2. **名称归一化确定性匹配**：匹配由程序做；结果三分：已存在→丢弃；不存在→采纳送生成；疑似重复→标记待人工确认。AI 只负责输出新增提示词。
3. 空素材库时跳过注入直接选模型。
4. 模型选择支持外部 AI（开发者自配接口）与本地千问（需做本地提示词适配：简化约束指令格式）。
5. 系统提示词结构含：预置模板、可替换变量、输出语言、JSON+分隔符输出格式、分镜粒度、风格标签库。
6. 输出必须能按"特殊分隔符/JSON"被程序自动分段（`C4`），并区分五类：角色/场景/物品/分镜/最终视频提示词（`E1–E5`）。

### SG2 素材生成与增量素材库（dot L52–L76，边 L275–L322）

主链：`E8 → GEN_PARAM 素材生成参数` → `GP1 分辨率`、`GP2 采样步数`、`GP3 采样器`、`GP4 CFG`、`GP5 种子`、`GP6 批量数量` → 四类生成器 `GEN1 角色参考图（仅新增）`、`GEN2 场景参考图（仅新增）`、`GEN3 物品参考图（仅新增）`、`GEN4 分镜参考图（仅新增）` → `F 特殊分隔符自动分段 → G 素材库核心参考源｜只追加版本，不覆盖历史内容`。
G 的属性节点：`G1 目录结构四类分目录`、`G2 命名规则 类型_序号_名称`、`G3 格式与尺寸`、`G4 数量上限每类9张`、`G5 素材优先级 角色>场景>物品>分镜`、`G7 增量更新：保留旧版本；新版本追加，不原位覆盖`、`G_META 素材版本元数据：global_id/version/SHA-256/来源/引用/审核状态`、`G6A 手动添加新素材入口 --默认不审核直接入库--> G`。
错误边：`GEN1–GEN4 --生成失败--> ERR1A 素材生成失败`（虚线）。
`G → G_VALID`（进入 SG3 审核）。

**规则/硬约束**：
1. 素材库是**唯一核心参考源**，且**只追加版本、不覆盖历史**；新版本追加，不原位覆盖（G、G7）。
2. 四类分目录；命名 `类型_序号_名称`；有格式与尺寸规范；**每类上限 9 张**；优先级 角色>场景>物品>分镜。
3. 每个素材版本必须携带元数据：`global_id / version / SHA-256 / 来源 / 引用 / 审核状态`（G_META）。SHA-256 即内容指纹，新版本必须重算（愿景 §三）。
4. 生成参数可配：分辨率、步数、采样器、CFG、种子、批量数量。
5. 只生成"程序匹配为新增"的素材（E8 送入）；分镜参考图也是素材一类。
6. 手动添加的新素材**默认不审核直接入库**（G6A+愿景 §九）。
7. 生成失败要有错误出口（ERR1A），并按爆炸半径处理（SG8）。

### SG3 素材版本审核与 LOCK（dot L77–L109，边 L323–L366）

主链：
`G → G_VALID 当前版本是否已有有效LOCK？`
- `--是：复用已审核版本--> G_LOCK 复用当前版本有效LOCK`
- `--否：新版本或未审核版本--> H5 审核参数：评分维度/阈值/候选上限/超时`
`H5 → H 当前项目审核模式`
- `--人工--> H1 人工审核：可持续重试；CNT1不生效`
- `--模型--> H2 模型审核：进入模型模式后CNT1从0开始`
人工支：`H1 → H1B 用户是否正在有效审核操作？`
- `--是--> H1C 有效操作期间暂停超时计时 → H1`
- `--否或持续闲置--> H3 人工等待超时：默认10分钟 → H4 切换至模型模式：记录日志/非阻断通知 → H2`
`H1 → HUMAN_RESULT 人工审核结果到达 → HUMAN_GATE 模型审核任务是否已启动？`
- `--否：人工模式直接提交--> HUMAN_DIRECT 采用当前人工审核结论 → H_COMMIT`
- `--是：发生并发竞争--> H_ARB`
模型支：`H2 → CNT1 CNT1+1：每个模型候选版本计一次；版本递增不清零 → MODEL_RESULT 模型审核结果到达 → H_ARB`
仲裁：`H_ARB H_arb：统一后端时间戳仲裁`
- `--人工时间戳早于模型完成时间--> H_MANUAL 人工结果胜出`；`H_MANUAL --虚线--> ABORT_SIGNAL`（中止仍在运行的模型任务）
- `--人工时间戳大于等于模型完成时间，或无有效人工胜出结果--> H_MODEL 模型结果胜出；迟到人工仅记日志`
三种胜出都 → `H_COMMIT 唯一最终结果提交点（只提交一次）` → `I 本轮审核结论/候选上限状态`
`I` 分支：
- `--通过--> LOCK 生成版本级LOCK：素材ID+版本号 → LOCK_SRC2 LOCK来源：HUMAN_PASS/MODEL_PASS → G_LOCK`
- `--未通过；人工模式继续--> K`；`--未通过；模型CNT1未到3轮--> K`
- `--模型CNT1达到3轮仍未通过--> N 从三轮候选中取最高分；标记FALLBACK → LOCK_SRC LOCK来源：FALLBACK_PASS → G_LOCK`
`K AI合规检查与提示词优化 → L 生成新素材版本：version+1；重新计算SHA-256 → RESUME_MODE 沿用当前审核任务模式`，人工模式→H1，模型/自动切换模式→H2。
`G6B 手动替换已有素材 → G6B_VERSION 创建新版本；保留旧版本；使用当前项目审核模式 → H5`。
`H1 --...--> H8 通知：弹窗+声音；可选QQ/飞书/钉钉`。
`ABORT_SIGNAL → MODEL_ABORTED 模型任务中断；禁止其迟到结果提交或触发下游流程`。
出口：`G_LOCK → J_IN`；`LOCK_SRC → J_IN`。

**规则/硬约束**：
1. **版本级 LOCK** = 素材ID + 版本号；有效 LOCK 可直接复用；"新版本或未审核版本"必须重新走审核（G_VALID 判断）。
2. **CNT1 语义**：只统计模型模式下的审核候选轮次，默认最多 3 轮；**版本递增不清零**；进入模型模式时从 0 开始；此前人工审核次数不计入 CNT1；人工模式下 CNT1 不生效（可持续重试）。
3. 人工超时默认 10 分钟；用户正在有效操作期间暂停计时；超时自动切模型模式，记录日志 + 非阻断通知（放通知区/报错栏，不霸占主屏）。
4. 并发仲裁用**统一后端时间戳**（H_arb）：人工时间戳早于模型完成时间→人工胜；否则模型胜，迟到人工仅记日志。
5. `H_COMMIT` 是**唯一最终结果提交点，只提交一次**。
6. 审核不通过：先 AI 合规检查/优化提示词（K），再生成新版本（version+1、重算 SHA-256，L），再按**沿用当前审核任务模式**重新审核。
7. 模型三轮仍不通过：从三轮候选中取最高分，标记 `FALLBACK`，LOCK 来源 `FALLBACK_PASS`。
8. 人工/模型通过：LOCK 来源 `HUMAN_PASS` / `MODEL_PASS`。
9. 手动替换：创建新版本、保留旧版本、使用当前项目审核模式重新审核；手动**新增**（G6A）默认不审核直接入库。
10. 中断模型任务后，迟到结果**禁止提交、禁止触发下游**（MODEL_ABORTED）。
11. 审核参数可配：评分维度、阈值、候选上限、超时；通知、降级策略用户可调（愿景 §三）。
12. 通知：弹窗+声音，可选 QQ/飞书/钉钉；非阻断。
### SG4 导演台与分段视频生成（dot L110–L135，边 L366–L402）

`E5 → J_IN 进入导演台 → J_PARAM 导演台参数`
- `JP1 默认分段时长10秒可调5/10/15`
- `JP2 默认分辨率1080P可选720P/4K`
- `JP3 默认帧率24fps可选30/60`
- `JP4 尾部帧数默认22可调`
- `JP5 首尾帧选取默认第一帧和最后一帧可手动指定`
- `JP6 显存档位自动检测可选低中高`
- `JP7 剪枝模型默认开启可关`
`JP1–JP7 → O 导演台自动分段与衔接` → `O1 自动取尾部22帧或前一帧无需手动切换`、`O2 主连贯性使用素材库参考图采用参考模式`、`O3 参考模式均可由节点自动处理`、`O4 导演节点自带显存配置简单处理即可`、`O5 显存节省策略（剪枝/分段采样/潜变量轻量化/FP8/tiledVAE/tiledDiT/unloadDiT）`、`O6 片头片尾角色由导演节点集合解决`、`O7 背景音乐需提进日程` → `P 分段视频生成` → `P1 人物不在尾部22帧时由素材库锁定`、`P2 场景物品服装由素材库锁定`、`P3 尾部22帧仅作动作镜头光线辅助连续` → `Q_OUT 分段视频清单：章节顺序/segment_id/版本/素材引用/段文件路径`；`P --视频生成技术失败--> ERR1B`。

**规则/硬约束**：
1. **连贯性主来源必须是素材库参考图**，不能是前一帧；人物不在尾部 22 帧时由素材库角色图锁定身份（P1/P2，愿景 §四）。尾部 22 帧只作动作/镜头/光线/节奏辅助连续（P3）。
2. 自动分段与衔接，无需手动切换；参考模式均可（O1/O3）。
3. 导演台能一次性直接输出约一小时完整内容（愿景 §四）。
4. 默认参数与可调项：分段 10s（5/10/15）、1080P（可选720P/4K）、24fps（可选30/60）、尾部帧 22、首尾帧、显存档位自动检测、剪枝模型默认开。
5. **显存节省在任何情况下都要做**（愿景 §六）；导演节点自带显存配置。
6. 片头片尾角色、背景音乐需纳入日程（O6/O7）。
7. 分段输出必须形成清单：章节顺序、segment_id、版本、素材引用、段文件路径（Q_OUT）。
8. 视频生成技术失败走 ERR1B 并按爆炸半径处理（SG8）。

### SG5 视频段审核与级联返工（dot L136–L165，边 L403–L440）

`Q_OUT → R_seg 仅审核当前视频段的当前版本 → SEG_BIND 审核对象绑定：segment_id+segment_version+AUDIT_ID → R1a 分段评分R1a：画面连贯/角色一致/动作合理/无闪烁 → R2 评分阈值默认70可调 → R3 当前段版本是否通过？`
- `--是--> SEG_PASS 记录本段版本、评分与审核来源 → SUCCESS_KIND 当前通过版本是否为级联段？`
  - `--否--> CASCADE_CHECK 该段变化是否影响后续段依赖？`
    - `--是--> Y2 标记下一受影响段待验证；为该段建立独立CNT3 → N1`
    - `--否--> ALL_SEG_DONE`
  - `--是--> N1_EDGE 验证第N段与第N+1段的相邻边界`
- `--否--> FAIL_KIND 当前对象是否为级联段？`
  - `--普通问题段--> CNT2_CHECK CNT2已达到3次重生成上限？`
    - `--否--> U 旧版本审核结论失效；仅重生成当前问题段 → REGEN 重新生成N段：段版本号+1 → CNT2 CNT2+1：只计当前普通问题段的重生成次数 → R_seg`
    - `--是--> Y 从三次重生成候选中选择最高分版本 → Y_SRC 来源记为REVIEW_FALLBACK；正常拼接并写入元数据 → CASCADE_CHECK`
  - `--级联问题段--> CNT3_CHECK CNT3已达到3次级联重生成上限？`
    - `--否--> N1 重生成当前级联段；只处理受影响段 → CNT3 CNT3+1：仅计当前级联段；与CNT2完全独立 → R_seg`
    - `--是--> N1_FALLBACK 从三次级联候选中取最高分；记录CASCADE_DEGRADED`
`N1_EDGE → N1_OK N与N+1相邻边界是否通过？`
- `--是--> N1_CLEAN 更新段级审核记录；清除本次待验证标记 → CASCADE_NEXT 是否还有被依赖关系影响的后续段？`
  - `--是--> Y2 → N1`
  - `--否--> ALL_SEG_DONE`
- `--否且CNT3未到上限--> N1`
- `--否且CNT3达到上限--> N1_FALLBACK → DEGRADED_EDGE 保留衔接降级标记；记录所选版本与评分 → CASCADE_CHECK`
`ALL_SEG_DONE 所有必需段级审核与边界验证完成 → READY_TO_SPLICE 允许进入最终拼接；保留所有兜底与降级元数据`。
错误边：`REGEN/N1 --视频生成技术失败--> ERR1B`。

**规则/硬约束**：
1. 审核对象绑定：`segment_id + segment_version + AUDIT_ID`；只审核当前段的当前版本；**旧版本审核结论失效**（重生成后必须重审）。
2. `R1a` 四维度：画面连贯/角色一致/动作合理/无闪烁；阈值默认 70 可调。
3. **CNT2**：只计"当前普通问题段"的重生成次数，默认 3 次上限；**CNT3**：只计"当前级联段"，与 CNT2 完全独立，默认 3 次上限；每个受影响级联段建立独立 CNT3（Y2）。
4. 级联：某段变化影响后续段依赖时，标记下一受影响段待验证并只重生成受影响段；衔接边界必须验证第 N 与 N+1 段；级联失败到达上限时取三次候选最高分并记录 `CASCADE_DEGRADED`，保留衔接降级标记与所选版本/评分。
5. 普通段三次候选取最高分时来源记 `REVIEW_FALLBACK`，正常拼接并写元数据。
6. 段级通过后仍需验证相邻边界；只有"所有必需段级审核与边界验证完成"才 ALL_SEG_DONE，才允许进入拼接；兜底/降级元数据必须保留到拼接。
7. 全自动 AI 审核，无人工审核（愿景 §五）。
8. 视频生成失败走 ERR1B 爆炸半径。

### SG6 最终拼接、整片审核与输出（dot L166–L191，边 L441–L472）

`ALL_SEG_DONE → READY_TO_SPLICE → SPLICE 整片拼接：按章节与段顺序合并最终选定版本 → ENC 成片封装参数` → `ENC1 音频自动拼接；可手动调整`、`ENC2 转场默认无；可选淡入淡出`、`ENC3 字幕默认不加；可启用`、`ENC4 水印默认不加；可启用`、`ENC5 输出格式：MP4默认；可选MOV/WebM`、`ENC6 编码：H.264默认，CRF18可调` → `PACKAGE_READY 完成封装；进入最终整片审核 → R_full 最终整片审核；仅在S_OUT之前执行一次 → R1b 整片评分R1b：叙事流畅/音画同步/节奏合理/无明显跳变 → FULL_DECISION 整片审核是否达到阈值？`

- `--否--> FULL_POLICY 整片审核失败策略：阻止输出或降级输出`
  - `--允许降级输出--> FULL_DEGRADED 记录FULL_REVIEW_DEGRADED、评分与原因 → S_OUT`
  - `--阻止输出--> WAIT_REVIEW 保留检查点；等待配置调整或人工处理`
`S_OUT → OUT_CFG 输出配置` → `OUT1 输出目录：output/项目名/日期/剧本名`、`OUT2 文件名：项目名/剧本名/日期/版本`、`OUT3 元数据：剧本/模型/参数/时间/版本/来源/审核分数/降级标记`、`OUT4 封面：默认第一帧，可指定` → `OUT5 第一阶段结束：本地成片交付 → OUT6 第二阶段接口预留：自动取下一剧本/发布`。

**规则/硬约束**：
1. 拼接按章节与段顺序合并**最终选定版本**；封装参数可配（音频自动拼接、转场、字幕、水印、格式、编码）。
2. **整片审核 R_full 只在 S_OUT 之前执行一次**；检查叙事流畅/音画同步/节奏合理/无明显跳变。
3. 整片审核失败必须二选一：阻止输出（保留检查点等待处理）或降级输出（记录 `FULL_REVIEW_DEGRADED` + 评分 + 原因）；**不允许静默放行**。
4. 输出目录/文件名/元数据/封面有明确规范；元数据必须含审核分数与降级标记。
5. 第二阶段接口预留（自动取下一剧本/发布）。

### SG8 异常、中断与断点恢复（dot L205–L216，边 L488–L506）

`ABORT_SIGNAL：中断仍在运行的模型任务 → MODEL_ABORTED 模型任务中断；禁止其迟到结果提交或触发下游流程`。
`ERR1A 素材生成失败 → ERR1A_B 爆炸半径`：局部→`GEN1`；中程：角色级→`GEN1`；全局：剧本级→`A`。
`ERR1B 视频生成失败 → ERR1B_B 爆炸半径`：局部→`REGEN`；中程→`N1`；全局→`A`。
`ERR2 用户主动取消中止 → RESUME`；`ERR3 断点续传触发 → RESUME`；`ERR4 版本回滚 → G`。
`RESUME 断点续传 → RESUME_TARGET 恢复到最近检查点`：素材阶段→`G`；导演台阶段→`P`；审核阶段→`R_seg`。
`PROJ7 --最近检查点/生成进度--> RESUME`。

**规则/硬约束**：
1. 中断信号必须能中断仍在运行的模型任务；被中断任务**禁止迟到结果提交、禁止触发下游**。
2. 错误必须定义爆炸半径（局部/中程/全局），不允许"一错全废"或"一错无感"。
3. 断点续传恢复到最近检查点，且按阶段（素材/导演台/审核）定位不同恢复目标；恢复源是项目的生成进度。
4. 版本回滚回到素材库（SG2 G）。

## 三、我认为"实现必须满足什么"（验收底线，R1 依据）

以下是我在后续代码盘点中要逐条核对的验收底线（不预设实现方式）：

1. **可运行主链**：项目→剧本→确定性注入→AI 拆解→新增素材→生成→素材审核/LOCK→导演台分段→分段审核/级联→拼接→整片审核→输出，必须存在真实可执行入口与工作流文件，而非只有文档或 UI 占位。
2. **状态真实落盘**：素材版本、LOCK、CNT1/2/3、审核记录、段清单、检查点/进度、项目数据必须是真实持久化数据（文件/DB），重启后可继续；不能只存在于内存或日志文本中。
3. **审核是真审核**：评分必须来自模型/真实算法输出，有维度、阈值、候选；禁止常量分、占位分、随机分冒充通过；禁止"没有审核器却永远 PASS"。
4. **计数真实生效**：CNT1/2/3 达上限必须真正进入 fallback/降级分支并留痕；版本递增不清零 CNT1；CNT2/CNT3 互不串数；人工模式不消耗 CNT1。
5. **旧版本失效真实生效**：重生成后旧 LOCK/旧审核结论不能被继续使用。
6. **仲裁真实生效**：并发人工/模型结果只能提交一次；迟到结果只记日志；中断后迟到结果不得提交或触发下游。
7. **连贯性来源真实生效**：导演台/生成工作流中必须真实引用素材库参考图；不能只靠前一帧或尾部帧；不能只有参数名没有接线。
8. **确定性注入真实生效**：程序生成并注入已有素材清单文本；AI 输出按名称归一化匹配后过滤；空库跳过注入。
9. **全本地**：审核模型/流程本地；不得为通过验收而偷偷调用外部 API 审核。
10. **可配置**：审核阈值/候选上限/超时/通知/降级策略、导演台参数、生成参数、封装参数至少可从配置读取并真正生效。
11. **可验证**：项目内应存在可执行的验证测试/校验脚本；测试必须真实断言上述行为，禁止空断言、skip 全绿、mock 掉被测逻辑。
12. **不破坏既有契约**：若存在既有测试/契约校验，修复不得削弱或删除其断言。

## 四、需求中需要后续重点核实的模糊点（不影响硬约束判定）

- dot 中 `A1B 素材库是否为空` 的判定粒度：项目素材库为空即可跳过注入；但 `E6` 的名称匹配仍必须执行（增量更新）。推断为空库时匹配退化为"全部新增"，无需特殊实现。
- dot 中 `H1 → H8 通知` 与 `H4 非阻断通知` 是同一通知体系；`H8` 可选 QQ/飞书/钉钉属于第二阶段/扩展，第一阶段需保证弹窗+声音+日志至少非阻断可用。
- "约一小时完整内容"是导演台能力要求，验收只能验证"一次运行可产出多段/长内容的结构能力"，不应强求真实 1 小时渲染（本机无 GPU）。
- `Z6/Z7 提示词默认配置、评分模型由我（需求方）写`：实现方只应提供可配置入口与默认模板，不得把评分模型硬编码为常量。
