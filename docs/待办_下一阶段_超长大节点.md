## 一、目标定义

**一个新节点** `BetterComfyUIOneStop`（名称待定，宣传名「剧核 DramaCore」）：
- 输入：一段剧本 + 模型选择（图像 checkpoint、H3 UNET/CLIP/VAE）+ API 配置；
- 内部完成：剧本 → 一次 API → 多提示词（E1–E5）→ 素材生成 → 入库（版本+指纹）→
  素材审核（模型/人工、CNT1、LOCK/FALLBACK）→ 导演台（段级生成）→ 段级审核（CNT2/CNT3/边界）→
  拼接封装 → 整片审核（R_full）→ 输出**一整个成片**（网页端可直接播放）；
- 输出：成片文件 + 提示词 JSON + 素材清单 + 审核报告 + 审计（全部在一个节点的输出面板可见）；
- **无外部自定义节点依赖**：把当前依赖的 6 个巨人包（MiniMaxH3Director / Smart / Chain /
  DNNodes / Storyboard-LLM / DeepSeek-connector）中**实际用到的逻辑复制进我们自己的插件**，
  不再要求用户另装；能拆出的纯函数直接 vendor（保留 license 声明）。

## 二、为什么现在不做

- 当前 4 个分步节点（素材生成/入库/审核、成片剪辑、视频审核）+ 大节点 Everything 已能工作。

## 三、技术方案候选（实现时三选一）

1. **节点内 orchestrator（推荐）**：单节点在 `execute()` 内通过 ComfyUI API 提交内部子图并轮询
   （类似 ComfyUI 的 `execution` 嵌套），风险：死锁/重入，需要严格超时与错误传播。
2. **Vendored pipeline**：把 H3 生成/审核/剪辑逻辑用 Python 直接实现（不走 ComfyUI 图），
   节点内直接调用模型；工作量最大，但真正“无依赖”。
3. **单节点 + 隐藏子图**：节点负责 UI/编排，实际子图仍由 ComfyUI 执行；需要 ComfyUI 内部 API 支持。
