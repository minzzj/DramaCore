## 二、真实生成尝试（以及它为什么失败）

### 做法

最小图：2×UNETLoader + CLIPLoader + 2×VAELoader → `MiniMaxH3Director`
（t2v、**256×256**、`total_frames=5`、`steps=1`），再接 `SaveImage` 输出。

### 过程中的两个小坑（都已修）

1. **`prompt_no_outputs`** —— 第一版没接输出节点，ComfyUI 直接拒绝：
   `{"error": {"type": "prompt_no_outputs"}}`。加 `SaveImage` 后通过。
2. **VAE 未出现在清单里** —— 权重是在 ComfyUI **启动之后**才下完的，
   它的文件清单是启动时扫描的。重启后正常。

### 实测时间线

```
HTTP 200   已入队 prompt_id = 363d113b-...
[1 分钟]  仍在执行（running=1）
...
[29 分钟] 仍在执行（running=1）
```

表面上"在跑"。但我测了**实际进展**：

| 指标 | 60 秒内变化 |
|---|---|
| 磁盘读取 | **0.0 MB** |
| CPU 时间 | **0.0 s** |
| 线程数 | **1** |
| 工作集 | **0.00 GB** |

**完全死锁** —— 不是慢，是卡死。所以手动终止了。

### 根本原因（数字说话）

| 项 | 大小 |
|---|---|
| ref2va 扩散模型 | 19.53 GB |
| 文本编码器（qwen3vl_32b） | 14.61 GB |
| **本次运行至少需要** | **34.14 GB**（仅权重，不含激活/帧缓冲） |
| 本机**物理内存** | **15.75 GB** |

**差约 18 GB。** 只能靠页面文件，而实测页面文件无法承载这种规模的
随机访问 —— 进程进入完全停滞状态（0 CPU / 0 磁盘 / 单线程）。

> 这是硬性资源墙，不是配置问题：即使把分辨率压到 256×256、帧数压到 5、
> 步数压到 1，**两个大权重仍然必须同时驻留**。

## 三、因此：这条未验证项有了**确切的未验证原因**

之前文档里写的是「需 ≥24GB 显存（本机 4GB）」—— 那是**显存**口径。
本轮补充了另一半事实：**本机连 CPU 回退路线也走不通**，
因为瓶颈同时在**系统内存**（差 18 GB）。

换机时的最小要求因此更新为两条，缺一不可：

| 资源 | 要求 | 依据 |
|---|---|---|
| 显存 | ≥24 GB | 实测峰值 22,016 MiB |
| **系统内存** | **≥64 GB** | 权重 34.14 GB 必须同时驻留 + 激活 |

（`docs/TARGET_MACHINE_HANDOFF.md` 已按此更新。）
