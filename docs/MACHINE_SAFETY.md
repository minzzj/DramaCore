# 机器安全：为什么这台机器会蓝屏，以及哪些操作不能做

> **背景**：2026-10-17 凌晨到上午，这台机器**蓝屏三次**。
> 本文记录已查明的确切原因，以及为了避免再次发生而加的保护。
> **这份文档优先于其他所有文档** —— 先保机器，再谈功能。

---

## 一、已查明的原因：内存耗尽（是我的责任）

三次崩溃的转储给出了**完全一致**的错误码：

| 时间 | 转储文件 | BugCheckCode | 参数 |
|---|---|---|---|
| 04:02:36 | `101726-6328-01.dmp` | **0x0000001A** | `0x42001` |
| 08:24:22 | `101726-7140-01.dmp` | **0x0000001A** | `0x42001` |
| 08:31:22 | `101726-6718-01.dmp` | **0x0000001A** | `0x42001` |

`0x1A` = **MEMORY_MANAGEMENT（内存管理错误）**。

**排除了硬件原因**：`Microsoft-Windows-WHEA-Logger` 在 10 月**没有任何事件**
（最近一次是 2026 年 2 月）。所以不是内存条故障、不是过热、不是供电异常。

### 根因

MiniMax H3 的权重规模与本机内存严重不匹配：

```
ref2va 扩散模型     19.53 GB
文本编码器           14.61 GB
本次至少需要         34.14 GB（仅权重，不含激活/帧缓冲）
本机物理内存         15.75 GB      ← 差约 18 GB
```

我做了两件把它推过临界点的事：

1. **CPU 真实生成尝试**（`scripts/try_real_run.py`）
   把可用内存压到 **0.48 GB**，页面文件在两块盘上疯狂换页，
   进程随后完全死锁（0 CPU / 0 磁盘 / 1 线程）。
2. **`submit_check.py` 把工作流提交进了 ComfyUI 队列**
   `/prompt` 的行为是「校验通过就入队执行」。
   我只要了校验结果，但任务已经进队列，随后开始加载那 34 GB。
   三次崩溃的时间与队列执行时刻吻合。

---

## 二、已经加上的保护

### 1. `submit_check.py` 现在默认「安全模式」

拿到校验结果后**立即** `POST /interrupt` + `POST /queue {clear:true}`，
并回读队列确认已空。校验答案在响应里就拿到了，**不需要真的执行**。

要允许执行必须显式加 `--allow-execute`，该参数会打印危险提示。

### 2. `try_real_run.py` 加了红线警告

文件头写明不要在这台机器上运行、原因与崩溃码，保留仅为记录实测方法。

### 3. ComfyUI 停机

出事时已立刻停掉 ComfyUI 进程并清空队列。

## 三、这台机器上的操作红线

| 操作 | 能不能做 |
|---|---|
| 启动 ComfyUI 看节点/网页界面 | ✅ 可以（只要不执行） |
| 跑 `pytest tests/` | ✅ 可以（纯 Python，不加载权重） |
| 跑 `validate_fusion_workflow.py` | ✅ 可以（只读 schema，不提交） |
| 跑 `build_fusion_workflow.py` | ✅ 可以（只读 schema） |
| 跑 `submit_check.py` | ✅ 可以（默认安全模式，会自动清队列） |
| **在 ComfyUI 网页上点 Queue 跑 H3 工作流** | ❌ **绝对不要** |
| **跑 `try_real_run.py`** | ❌ **绝对不要** |
| **任何让 H3 权重进内存的操作** | ❌ **绝对不要** |

### 真实出片需要什么

换到同时满足以下两条的机器：

| 资源 | 要求 | 依据 |
|---|---|---|
| 显存 | **≥ 24 GB** | 实测峰值 22,016 MiB |
| **系统内存** | **≥ 64 GB** | 权重 34.14 GB 必须同时驻留 + 激活 |

> 注意：「没有 GPU 就退回 CPU」在这个模型上**不成立** ——
> 内存同样是硬门槛。

## 四、如果还想用这台机器看图

ComfyUI 可以启动，**只要不在网页上点 Queue**：

```powershell
cd '[PROJECT-ROOT]\.comfyui'
& '..\.comfyenv\Scripts\python.exe' main.py --cpu --listen 127.0.0.1 --port 8188 --disable-auto-launch
```

然后浏览器打开 http://127.0.0.1:8188 ，可以看节点、连线、拖工作流。
**看完直接关掉浏览器，不要点 Queue。**

## 五、我自己接下来的纪律

1. **不再做任何真实生成的尝试**，这台机器做不到，已用两次代价确认。
2. **任何会入队执行的脚本，默认必须清队列**；`--allow-execute` 只作为显式逃生门。
3. 涉及大模型的验证，**先算内存够不够**，不够就只做静态/契约级验证并明确标注"未验证"。
4. 每轮结束把状态写进 `docs/RESUME.md`，断电后能立刻接上。
