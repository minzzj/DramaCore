# 双卡效率与质量测算报告（RTX 5090 32GB 生产 / RTX 4090 48GB(改) 测试）

> 用户本轮新增要求（2026-10-18 凌晨）：
> ① 正式生产环境显存 **5090 32GB**，测试机 **4090 48GB**；
> ② 必须把整体显存控制在 **32GB 以下**；
> ③ 按两张卡的参数，计算正式环境的**效率与质量**并出测试报表；
> ④ 测试机上发现的问题立刻修；测试机环境要提前给出预装清单（CUDA/cuDNN/PyTorch/依赖）。
>
> **口径（重要）**：本报告是**理论测算 + 测试方案**，不是"已实测"。所有绝对时间、
> 显存峰值都必须在真机用 `nvidia-smi` / 实际跑段校准后才能写成"已验证"。
> 表内区间来自：模型文件磁盘实测体积（本仓库）、公开 GPU 规格、视频 DiT 的
> 计算/带宽混合瓶颈模型；误差预计 ±25%~40%。

## 一、硬件与软件参数对照

| 项 | RTX 4090 48GB（测试机，改装卡） | RTX 5090 32GB（正式生产） |
|---|---|---|
| 架构 | Ada Lovelace (AD102) | Blackwell (GB202) |
| CUDA 核心 | 16384 | 21760 |
| 显存 | 24GB 原厂 → **48GB 改装**（实际可用 ≈47GB） | **32GB GDDR7**（实际可用 ≈31GB） |
| 显存带宽 | 1008 GB/s | **1792 GB/s**（≈1.78×） |
| 张量算力（FP8 稠密） | ≈660 TFLOPS | ≈838 TFLOPS（≈1.27×） |
| FP4 支持 | ❌ 不支持 NVFP4 硬件 | ✅ 原生 NVFP4 |
| 功耗/散热 | 450W（改装卡散热/供电风险↑） | 575W |
| 驱动最低 | 550.x（CUDA 12.4）；cu128 需 570+ | **570+/580+**（Blackwell） |
| CUDA / cuDNN | 12.4 / 12.8 均可；cuDNN 9.x | **CUDA 12.8+ / cuDNN 9.7+** |
| PyTorch | 2.5~2.8 + cu124/cu128 | **2.7+ cu128**（sm_120 支持） |
| RAM 建议 | ≥64GB | ≥64GB（推荐 96~128GB） |

> 5090 是 sm_120；PyTorch 必须 ≥2.7 + cu128 才原生支持，否则回退极慢/报错。

## 二、模型显存账（本仓库实测文件体积）

| 模型 | 体积 | 说明 |
|---|---|---|
| 视频 UNET `minimax_h3_ref2va_pruned_int8_convrot` | **19.53 GB** | int8 剪枝 |
| 文本编码器 `qwen3vl_32b_minimax_h3_nvfp4_awq` | **14.61 GB** | **NVFP4 量化（Blackwell 原生；4090 不支持硬件 FP4）** |
| 视频 VAE `minimax_h3_video_vae_fp16` | 4.85 GB | |
| 音频 VAE `minimax_h3_audio_vae_fp32` | 0.56 GB | |
| Turbo LoRA（4step） | 0.29 GB | |
| **合计** | **≈39.84 GB** | 不含图像模型、激活值、CUDA 上下文 |

关键结论：
1. **39.84GB > 32GB** → 5090 生产环境**必须分阶段加载**（文本编码器编码完再卸载，再上 UNET+VAE）；
2. 4090 48GB 可一次性常驻（≈47GB 可用，理论上装得下 39.84 + 激活 4~6 ≈ 44~46GB，**很紧**，建议同样分阶段更稳）；
3. **4090 最大的隐患**：NVFP4 文本编码器在 Ada 上无硬件支持，ComfyUI/transformers 通常要
   dequant 成 BF16（32B≈64GB，必爆）或 FP8（≈32GB，需另找 FP8 版本）；
   → **测试机要么准备 FP8 版文本编码器，要么把文本编码器放 CPU（需 ≥64GB 内存，速度慢）**。
   这一点会直接影响测试机能否复现正式环境，**必须先验证**（见环境清单）。

## 三、32GB 显存控制方案（生产 5090）

| 阶段 | 驻留内容 | 峰值估算 | 是否 <32GB |
|---|---|---|---|
| A 文本编码 | 文本编码器 14.61 + 激活 ≈1 | ≈16 GB | ✅ |
| B 视频扩散 | UNET 19.53 + LoRA 0.29 + 视频 VAE 4.85 + 音频 VAE 0.56 ≈ 25.23 + 激活 3~5 | **28~30.5 GB** | ⚠️ 贴线，必须配 tiled VAE + batch=1 + 显存预留 |
| B' 若 1080p | 以上 + 更高激活/缓存 | 30~34 GB | ❌ 高风险 → 建议生产先 **720p** |
| 4090 一次常驻 | 39.84 + 激活 4~6 | 44~46 GB | ✅（<47GB）但贴线 |

落地措施（会写进 GPU 总流程说明区 + 环境清单）：
- ComfyUI 启动：`--reserve-vram 1.5`（给系统/上下文留量）；`PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`；
- 分两段点队列（或第二阶段自动阶段化）：先文本编码+素材，再 UNET+VAE 出片；
- VAE 一律 **tiled**；batch=1；生产分辨率先 **720p**（1080p 需实测）；
- 全程 `nvidia-smi --query-gpu=memory.used --format=csv` 采样，峰值 >30.5GB 即判失败并回退。

## 四、效率测算（相对值 + 绝对时间公式）

### 4.1 相对效率（理论）
- 计算：5090/4090 ≈ **1.27×**（FP8 稠密）；带宽：**1.78×**；
- 视频 DiT 是"计算 + 带宽"混合瓶颈，有效加速比取区间 **1.4×~1.7×**（模型/分辨率不同会漂移）；
- 5090 额外优势：文本编码器 NVFP4 **原生**跑（4090 需降级/CPU 回退），文本编码阶段可能快 2× 以上；
- 5090 额外成本：32GB 装不下全模型 → **分阶段重加载**。按 NVMe 5GB/s 计，
  加载 14.61+19.53+5.41 ≈ 39.55GB ≈ **8~13 秒/批次**；若每批 10 段（10 分钟级），
  重加载开销 **≈1.5%~2%**，可接受。

### 4.2 绝对时间公式（用测试机实测值 t_seg 校准）
```
4090-48G：总时长 ≈ N × t_seg + 加载开销(≈0，常驻)
5090-32G：总时长 ≈ N × (t_seg / S) + B × T_reload
    S = 1.4~1.7（有效加速比，实测校准）
    N = 段数（1 小时片长 ≈ 360 段，10s/段）
    B = 批次数（每批 10 段则 36 批），T_reload ≈ 10s
```
示例（**仅示例，待实测**）：

| 单段实测 t_seg（4090） | 4090 总时长(360段) | 5090 总时长(360段, S=1.55) |
|---|---|---|
| 30s | ≈3.0 h | ≈1.95 h + 6min ≈ **2.05 h** |
| 60s | ≈6.0 h | ≈3.9 h + 6min ≈ **4.0 h** |
| 120s | ≈12 h | ≈7.8 h + 6min ≈ **7.9 h** |

### 4.3 正式环境（5090-32G）效率结论（理论）
- **效率**：同参数下预计比 4090-48G 快 **1.4~1.7×**（文本编码阶段可能更快）；
- **质量**：同一权重、同一 prompt/seed/分辨率/步数 → 画面质量**等价**；差异仅来自
  文本编码器精度路径（NVFP4 vs FP8/dequant），通常不可见，但需用同 seed 对比 PSNR/SSIM 验证；
- **稳定性**：5090 32GB 的瓶颈是**显存而非算力**，分阶段调度做对就不会 OOM；
  4090-48G 改卡本身有散热/供电/驱动稳定性风险，测试机跑出的崩溃要先区分"改卡问题"还是"产品问题"。

## 五、质量评估方案（正式环境）
| 维度 | 指标 | 方法 | 合格线（建议） |
|---|---|---|---|
| 完整性 | 段数/总时长/音轨覆盖 | ffprobe + 计划清单比对 | 段数一致；时长误差 ≤2%；音频覆盖 ≥99% |
| 剪辑性 | 单文件、无重复/跳段、边界 | 拼接报告 + 边界相似度 | 单文件；边界相似度 ≥55；无重复段 |
| 清晰度/构图 | 本地评分器 `画质/构图` | `bettercomfyui.review.local_scorer` | 均值 ≥70（阈值可配） |
| 稳定性 | 闪烁/跳变 | 帧差尖峰占比 | 无闪烁 ≥70；无明显跳变 ≥70 |
| 音画 | 同步 | 音视频流时长差 | 差 ≤0.2s |
| 一致性 | 角色/场景 | 参考图对照（语义模型或人工抽检 3 段） | 人工检查无角色丢失 |
| 语义质量 | 叙事/构图 | 人工抽检 + （可选）语义评分模型 | 抽检通过 |

> 说明：本地评分器是**真实像素/帧统计的启发式**（非语义模型）；"质量是否高"的最终判定
> 需要人工抽检 + 可选语义模型，报告里会如实区分"机器可证"与"人工判断"。

## 六、测试机（4090-48G）与正式机（5090-32G）对比测试协议

1. 相同输入：同一剧本、同一 prompt、同 seed、同分辨率/步数/fps/编码参数；
2. 记录：每段耗时、模型加载时间、`nvidia-smi` 峰值/均值、RAM 峰值、是否 OOM/降级；
3. 每次跑 3 段（热身）+ 10 段（稳态），计算 `t_seg` 与显存峰值；
4. 5090 用 `S = t_4090 / t_5090` 校准后回填第四节表格，再推算 1 小时片总时长；
5. 质量：两卡同 seed 各生成同一段，抽帧计算 PSNR/SSIM（若精度路径不同，预期轻微差异），
   并人工抽检 3 段；结论写"等价 / 轻微差异 / 明显差异"。

## 七、必须实测校准的项目（本报告未证）
1. 两张卡的真实 `t_seg`、真实显存峰值（尤其 5090 分阶段峰值是否 <30.5GB）；
2. 4090 上 NVFP4 文本编码器能否加载（不能则需 FP8/CPU 回退方案，会改变测试口径）；
3. 720p 与 1080p 的显存/质量/耗时差异；
4. 1 小时成片的拼接/编码耗时与磁盘占用；
5. 5090 驱动/PyTorch/cuDNN 组合的实际可用性（Blackwell 兼容性）。

## 八、RTX 4090-48G 实测数据（2026-10-18，真机；供回填/校准）

> 来源：ROUND36 目标机实机验证（H3 生产镜像，864x480@24fps、5.17s/段、turbo 工作流）。

| 指标 | 冷启动（首次含加载） | 热启动（模型缓存 + 随机种子重算） |
|---|---|---|
| 单段耗时（5.17s 片段） | **112.83 s** | **82.45 s** |
| 显存峰值 | **40.93 GB** | **45.58 GB** |
| 输出规格 | 864x480 / 24fps / 含音频 / ≈1.1MB | 同左 |

**实测结论（替代理论区间中与 4090 相关部分）**：
1. H3 全链在 4090-48G 上峰值 **45.58GB**（几乎吃满 48G），**32GB 的 5090 必须分阶段**；
2. 冷/热差 ≈30s 主要是模型加载；分阶段后每次切换的加载开销需在 5090 上实测；
3. 按本机实测单段 82.45s 外推：360 段 ≈ **8.2 小时**（4090、5s 段；10s 段需另测）；
4. 口径提醒：本机测试的是**镜像自带 H3 Turbo 工作流**，与我方导演台节点/工作流不同；
   结论用于「显存红线 + 量级」，精确生产数字要以 5090 + 生产工作流实测为准。

## 九、高分辨率效率更正（重要，2026-10-18 重测）

> 本章节推翻了第八节中用 864×480（0.4MP）测出的效率口径——用户指出“正常生成也要高清”。
> 4090-48G 实测：**1280×736（0.9MP）单段 232.03s、显存峰值 41.09GB**；
**1920×1088（2.0MP）802.28s、42.43GB**（vs 480p 的 82.45s）。
> 1 小时片（360 段）720p ≈ **23.2 小时**；720p 峰值 41GB > 32GB → **5090-32G 不能直接 720p 全驻留**，
> 生产推荐「480p 生成 + 模型超分到 1080p」（实测 120~125s/段，宣传片 5/5 成功）。
> 详见 `docs/ROUND39_高分辨率效率修正报告.md`；1080p 原生结果见该报告第四节更新。
