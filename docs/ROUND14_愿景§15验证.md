## 五、本轮挖出两条**实测契约事实**（不猜）

这两条是踩出来的，写下来免得后人重踩：

### 事实 1：规范 JSON **只认规范英文键**

模型若用中文键输出 JSON：

```
{"章节": [...], "人物": [...]}
```

会被判 `$.assets [missing_field] 缺少必填字段 assets（可以是空数组）`。
JSON 路径要求 `assets` / `chapters` / `segments` / `id` / `asset_type` 等**规范键**。

### 事实 2：中文标签**只在「分隔符文本」格式生效**

`_SECTION_ALIASES`（角色/人物/场景/物品/分镜/章节/分镜段…）与
`_FIELD_ALIASES`（编号/名称/提示词/素材引用/时长…）**只被分隔符解析器使用**
（`validate.py:569` 在 `_parse_blocks` 里）。

所以「特殊分隔符标记」**不是 JSON 的另一种写法**，而是**另一条独立支持的格式**：

```
=== 章节 ===
章节id: CH001
标题: 雪夜
=== 分镜段 ===
序号: 1
提示词: 雪夜长街，林澈独行，镜头缓慢推进
素材引用: A1, A2, A4
时长: 10
=== 人物 ===
编号: A1
名称: 林澈
提示词: 少年剑客，白衣，长发束起，冷峻，全身像
```

**实践含义**：配置 `output_format: json` 时，提示词模板必须要求模型用规范英文键；
要中文标签就得配 `output_format: delimited`。两者不能混。

## 六、我自己的一个错误（已修正）

第一版汇总脚本把「本次新生成的素材」误报成了「复用既有」——
因为我拿引用去比素材的**名称**，而引用里写的是**编号**（`A1`）。

结果：`reuse` 数成了 7 而不是 1，看着像"大量复用"，
其实是**把新生成误报成复用**——正好是这条链最不该出错的地方（R1 要求
"明确匹配已有素材就复用、不重复生成"，反过来误报会导致重复生成）。

已改为**同时比对编号与名称**，并把标签写清楚（`本次新生成` / `复用既有`）。
