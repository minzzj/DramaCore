# 流程事故与修复记录（STAGING OVERWRITE INCIDENT）

> 2026-10-17 凌晨记录。**这是一个我自己造成的、反复发生三次的事故**，
> 记下来是因为它比任何单个 bug 都危险：它**静默地**抹掉已经修好的东西。

---

## 一、事故是什么

本项目的写入路径曾是：

```
我在工作区直接编辑  →  从暂存区（%TEMP%\bcui_stage）Copy-Item 覆盖  →  修复被抹掉
```

因为 H: 卷上 `write` 工具不能直接写（`EISDIR`），我采用了"写暂存 → 复制到工作区"的方式，
**但暂存副本会过期**：一旦我在工作区就地改了文件，暂存区那份就变成旧的。
之后再发布别的改动时整份覆盖，就把工作区的修复抹回去了。

### 三次事故的实际后果

| 次数 | 被抹掉的东西 | 后果 |
|---|---|---|
| 1 | `make_r2v_group` 的 `first_frame`/`last_frame` | r2v 组缺字段，行为不可预期（**契约测试抓到了**） |
| 2 | `_register_routes()` 调用 + 融合/素材节点注册 | 节点全正常，但**所有 `/bettercomfyui/*` 路由 404**，启动日志"看起来正常" |
| 3 | 一批修复一起丢：`_enum_to_value` 的 Enum 判断、`detect_vram_tier`、`_probe_comfyui(base_path)`、`PromptParams` 8 键、`MovieMetadata.generation_provenance`、`GlobalParams.comfyui_base_path`、`nodes.py` 控件接wiring | `dump_config` 报 `RepresenterError`、`doctor` 缺档位、配置加载直接抛错（**`pytest` 全红**） |

第 3 次是"最幸运的一次"——`ConfigError: 配置段 [prompt] 存在未知键` 让它**吵得很响**。
如果那次丢的是一个没有测试覆盖的字段，我会**带着旧代码交付并声称已修好**。

---

## 二、为什么测试没能在第一时间全部拦住

三次里只有第 1 次立刻被测试抓到（`test_fusion_contract.py` 的 AST 字段比对）。
第 2 次的守卫当时**还不存在**（是事故之后才补的）。
第 3 次靠的是**别的**测试红掉才暴露。

教训：**「有一个测试」不等于「这个功能受保护」。** 守卫必须针对**具体失败模式**写，
而且最好能**静态**检查（不依赖运行时环境）。

---

## 三、修复（三层防御）

### 第 1 层：改掉发布语义（根除根因）

`scripts/publish.py` 现在**默认不覆盖工作区已有文件**：

```
[保留工作区] bettercomfyui/cli.py —— 工作区版本与暂存区不同，按安全规则**不覆盖**
```

只有在显式 `--overwrite` 时才覆盖，且覆盖后**必定**跑验证测试。
暂存区的正当用途只剩一个：**发布工作区里还没有的新文件**。

### 第 2 层：发布即验证

`publish.py` 把「复制 → 语法检查 → 契约测试」合成一步，任何一步失败就非零退出。
实测有效：第 3 次事故中它**成功地把 `test_phase1_gaps` 的失败报了出来**，
所以我没有带着坏文件继续往前走。

### 第 3 层：针对具体失败模式的静态守卫

| 守卫 | 抓什么 | 位置 |
|---|---|---|
| AST 字段比对 | 我的组结构与真实 `pack_*` 不一致 | `tests/test_fusion_contract.py` |
| 源码级断言 | `__init__.py` 里丢了模块级 `_register_routes()` 调用 | `tests/test_comfy_plugin.py` |
| AST 未定义全局名扫描 | `routes.py` 里裸 `__version__`（会让路由 500） | `tests/test_comfy_routes.py` |
| 默认配置可移植性 | `default.yaml` 混入机器绝对路径 | `tests/test_foundation.py` |
| 默认配置可复现 | `default.yaml` 与 `Config()` 序列化不一致 | `tests/test_foundation.py` |

**AST 全局名扫描**这条特别值得说：`__version__` 那个 bug 出现过**两次**，
两次都让 `/bettercomfyui/doctor` 返回 500，而面板打开后的第一个请求恰好就是它。
用"调用一次处理器"的测试抓不稳（缺依赖时会 skip），
用 AST 静态扫描则**永远能抓**。

### 第 4 层：对账脚本

`%TEMP%\bcui_reconcile.py` 一次性检查 7 项关键行为，
用**行为探测**而不是文本匹配。出事后跑它就立刻知道丢了什么。

---

## 四、现在的规则（写给未来的自己）

1. **工作区是唯一真源。** 已进入工作区的文件，永不用暂存副本覆盖。
2. 需要"发布"时跑 `python scripts/publish.py`，不要手写 `Copy-Item`。
3. 覆盖已有文件必须显式 `--overwrite`，并且事后跑全量测试。
4. 新增守卫时问一句：**这条守卫能抓住"代码被换回旧版"吗？**
   抓不住就补一条静态的。

---

## 五、这次事故的正面价值

它逼出了三条**真正有价值**的守卫（源码级路由注册断言、AST 全局名扫描、
默认配置可移植性/可复现性），并且让 `publish.py` 从一个"方便脚本"
变成了一个**会拒绝危险操作的守门人**。

也幸好第 1 次事故有 `test_fusion_contract.py` ——
那条测试用 AST 从**真实导演台源码**里抄字段，是这个项目里最有价值的一条测试。
它当时抓到了我自己写错的 r2v schema；如果它不存在，那个错误会一路带到线上。
